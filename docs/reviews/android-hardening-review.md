# Android hardening review for the Offline Translator fork

Status: researched design and verification plan, 2026-10-24. No claim of MASVS compliance. No new hardening policy has been deployed. The accompanying source changes remain unbuilt drafts.

## Goal and boundaries

Protect typed/shared text, images, microphone input, translated documents and user control without breaking offline translation, third-party integration, downloads, recovery, accessibility or battery behavior. Distinguish malicious-code evidence, accidental disclosure, optional features and unverified hypotheses.

Attackers considered: another ordinary app; a malicious website/frame; an untrusted local-network peer; a compromised download origin/catalog; and diagnostic/backup recipients with greater access than an ordinary app. A hostile privileged OS is outside the protection an app sandbox can guarantee. User-selected speech recognizers, keyboards, backup providers and visited websites are separate trust boundaries.

Use Android's platform documentation plus applicable OWASP MASVS storage, platform, network, code and privacy controls. Use MASTG tests for evidence. Select current tests: the MASTG index marks many old monolithic tests deprecated. A source scan or a newly added flag does not constitute runtime verification.

## Decisions, tradeoffs and acceptance

| Area | Proposed direction | What can go wrong with a simplistic fix | Required proof |
| --- | --- | --- | --- |
| Diagnostics | Remove raw user payloads; retain predictable event diagnostics. Review exception messages and native logs. | Disabling all diagnostics can conceal download/engine failures; debug-only guards still expose data in diagnostic builds. | Use fictional unique canary text across typing, dictionary, OCR, sharing and Binder success/failure paths. Check Logcat and captured bug-report material for both build modes; confirm UI/callback results and useful static failures remain. |
| Speech input | Offer clearly described provider-based input; design a strict on-device path where supported and fail closed in that mode. | EXTRA_PREFER_OFFLINE can be ignored. Direct SpeechRecognizer requires new microphone permission/lifecycle handling; API 31 methods cannot be called unguarded on minSdk 23. Unsupported languages/models must not silently fall back to network. | Exercise offline-only, no-provider, unsupported-language, permission-denied, cancellation, rotation and backgrounding cases. Monitor provider traffic separately from the translator. Destroy recognizer resources and ensure the microphone stops. |
| HTTP API | Retain off-by-default and localhost-by-default behavior. Define an authenticated, bounded LAN mode before exposing it as hardened. | Localhost is not caller authentication; CORS is not authentication; a bearer token over plaintext LAN can be intercepted. A new required token can break LibreTranslate clients. | Test authorized/unauthorized local and LAN clients, malicious Origin/Host, oversized/slow requests, concurrency, token reset/rotation and legitimate clients. Check listener closure after disable/process death/restart. Do not broaden bind scope to solve a connection failure. |
| Android IPC | Inventory exported components and their intended callers, then validate inputs, caller policy, URI grants and bounds. | Setting every component exported=false breaks share intents, TTS, tiles, assistant and documented AIDL clients. A signature-only permission excludes independently signed legitimate clients. | Use an independently signed test client; malformed/oversized requests must fail safely, granted URIs remain scoped, and normal share/TTS/assistant/AIDL workflows continue. |
| Browser bridge | Treat websites and every iframe as untrusted. Keep native capabilities minimal, bound inputs/work and reject stale responses; investigate frame/origin-aware alternatives. | JavaScript-interface tokens are not proof of frame origin. Blanket JavaScript/origin restrictions break the feature's purpose of translating arbitrary websites. Message channels also need origin validation. | Controlled same-origin/cross-origin frames, redirects and navigation during pending translation; forged token/nonce, large image/text requests and request floods. Verify there is no path to app-private files or unrelated drafts, and ordinary website translation still works. |
| Storage and backup | Keep private data in the sandbox/cache; enumerate real persisted data before excluding sensitive material from backup. Define retention and recovery. | Disabling all backups can remove settings/recovery; encrypting all public model files adds complexity and I/O without protecting private text. Restored ciphertext without its key can become unrecoverable. | Inspect backup output and restored app, including device transfer, with fictional documents/preferences. Check denial/low-space/interrupted-write cases. Confirm imported/transformed documents are in intended cache locations and document cleanup semantics. |
| Downloads and TLS | Preserve hostname/certificate validation and HTTPS. Validate metadata, sizes, installed paths and archive extraction; review model provenance independently. | Pinning can break certificate rotation and third-party hosts. A trust-all workaround is worse. Checksums from the same compromised catalog establish consistency, not publisher authenticity. A hardcoded CDN allowlist can break supported custom catalogs. | Reject invalid certificates/hostnames, truncated/corrupt packs, traversal entries, unexpected redirects/schemes and unsafe install paths. A failed update must leave a usable previous installation or a clear repair state. Test legacy Android trust support rather than deleting it blindly. |
| Services and performance | Restrict work to intended feature lifetimes and profile before changing scheduling. | Disabling boot/process restoration wholesale can break enabled notifications/API; overly aggressive cancellation can lose work; moving work to IO without request identity can allow stale results to overwrite newer state. | Measure idle, screen-off, cold launch, download, document and live-OCR CPU/wakeups/frames separately. Verify enabled-feature recovery and no unnecessary work with features disabled. Compare equivalent release/profileable builds and model sets. |
| Native/build supply chain | Inspect the actual release artifact, dependencies and compiler mitigations; preserve source/build provenance. | Extra compiler flags can be redundant or incompatible; stripping symbols and obfuscation do not establish memory safety. Debug APK behavior cannot qualify a signed release. | Record source/native dependency revisions, dependency review, signing identity, merged manifest, debug flags and ELF properties. Test malformed untrusted inputs with sanitizers/fuzzing in an appropriate harness; inspect the final release again. |

## Evidence that changes our choices

- Android's speech docs explicitly say EXTRA_PREFER_OFFLINE defaults to false and can have no effect depending on implementation. On-device recognizer creation and availability methods start at API 31. Switching from external recognition UI to an in-process recognizer also changes permission and lifecycle responsibilities. A one-line preference is not the promised security boundary.
- Android discourages routine certificate pinning because server/certificate changes can strand installed clients. This app has external model hosts, configurable catalogs and legacy Android TLS support. No pinning change is justified by the present findings. LegacyTrustAnchors adds ISRG Root X1 alongside system roots only below Android 7.1.1; it is not a trust-all manager. Any replacement needs actual legacy-device compatibility tests.
- Android documents that addJavascriptInterface is visible to all frames and does not establish the caller frame's origin. Existing randomized names/tokens and payload bounds are useful observations, not a complete origin-isolation proof. Do not infer an exploit solely from use of the API or assume the token solves it.
- Current imported/translated documents use cacheDir in the reviewed code. Android excludes cache from Auto Backup by default. The backup finding must therefore remain "eligible app data may be backed up," not "all translated documents go to Google."
- Read-only ELF inspection of all six ARM64 libraries in the supplied older debug APK found non-executable GNU_STACK, GNU_RELRO and BIND_NOW. Four reference __stack_chk_fail; absence of that symbol in two others alone does not prove missing protection. These observations do not qualify a future release binary or prove absence of memory bugs. Adding redundant flags is not the immediate priority.
- The native logger is capped at Info. A trace-only input dump in translator-rs is not enabled by that Android configuration. Conversely, Kotlin logs already expose actual payloads. Address the demonstrated path first.
- A relevant upstream logging fix is already open as PR #350. Review/rebase or reconcile it before creating another public proposal; do not adopt its older file layout or unrun-test claims as verified for this source revision.

## Smallest justified next change

### Risk prioritization after reassessment

This is one reviewer's reassessment of source evidence, not an independent penetration test. Order reflects exposure, preconditions, impact, evidence confidence and change risk. No critical compromise or silent translation upload has been demonstrated. Priority is conditional on enabled features rather than a CVSS score assigned without exploit validation.

| Order | Finding / confidence | Priority and rationale | Next proof / escalation condition |
| --- | --- | --- | --- |
| 1 | User payloads in diagnostics — confirmed source behavior | Fix first. A low-complexity change addresses actual private text and dictionary/message logging. General Logcat access is restricted on modern Android, so this is not evidence that every ordinary app can read translations. Privileged tooling and diagnostic exports remain relevant. | Verify canaries do not appear in debug/release success and failure logs while results and errors still reach the intended UI/callback. The checked app R8 rules have no explicit Log.* stripping rule; inspect the actual compiled release before claiming its runtime behavior. |
| 2 | External speech recognition — delegation confirmed; network transmission conditional | High privacy priority when microphone input is used. An offline-app expectation can be violated by an online provider; without microphone use this path is not active. Audio leaving the device has not been observed. | Clearly disclose the provider boundary and implement/test a genuine strict offline path before promising it. Test absent/unsupported recognizers and cancellation. Monitor the provider as well as this app; an offline-preference extra alone is insufficient. |
| 3 | HTTP API — disabled/local defaults confirmed; unauthenticated plaintext service confirmed when enabled | Before LAN use, treat this as the highest conditional security priority. Reachable callers can consume local translation resources and LAN client traffic lacks TLS. Do not imply the API exposes arbitrary prior drafts: the reviewed routes translate client-supplied content and file downloads use random identifiers. | Keep off/local defaults; test caller access, transport, limits and lifecycle before enabling hardened LAN mode. Multipart fields are read into memory without an explicit cap in the examined handler; verify framework limits and large/slow-request behavior. Demonstrated resource exhaustion or unintended file access would raise urgency. |
| 4 | WebView native bridge / exported IPC — attack surface confirmed; unauthorized exploit unproven | Investigate next and before a public release of these features. Untrusted pages and other apps cross into native functionality, but existing tokens/bounds and Android component permissions matter. A bridge API or exported service alone is not a demonstrated vulnerability. | Use malicious frames/navigation and an independently signed IPC client. Test access to unrelated private data and request/cancellation budgets. Reproducible unauthorized access or controllable native parsing would move this above the current logging work. Preserve intended website translation and clients. |
| 5 | Native/model supply chain — general high-impact attack surface, no specific exploit identified | Release gate and ongoing maintenance. Check dependency/model provenance, parser inputs and final artifact properties without inventing a critical vulnerability from native-code use. | Dependency review and controlled malformed-input/fuzz cases; re-check release ELF/signing/build provenance. Known exploitable dependencies or demonstrated pack/path validation failure would escalate immediately. |
| 6 | Backup/storage policy — permissive configuration confirmed; sensitive backup contents unverified | Inventory before changing policy. Reviewed input/output document copies use cacheDir, which Android excludes by default. Actual eligible files, provider/settings and backup quota determine exposure. Do not claim all translations are uploaded or disable recovery indiscriminately. | Inspect a controlled backup/restore and device-transfer result with fictional data. Confirmed private text in an unintended backup raises this priority. |

Boot initialization, live-OCR load and synchronous dictionary work belong in a separate performance track unless they reveal unintended capture, unauthorized triggering or a reproducible denial of service. The user's screen lag remains a product priority; it does not become a security incident simply because CPU/battery use is involved. Do not let speculative hardening displace profiling and functional recovery.

Defer broad anti-root/attestation controls, arbitrary encryption and certificate pinning unless a specific threat justifies them. Highest-impact controls can still be wrong for a FOSS offline app if they introduce network dependence, exclude supported devices, strand downloads or prevent data recovery.

Retain the draft removals of demonstrated payload logs and the narrowly scoped language-filter cache improvement. Their completed checks are source integrity, patch applicability and diff review only. Do not claim they are build-tested or comprehensively eliminate sensitive diagnostics. Keep speech-provider, LAN authentication, backup, exported-component and browser-architecture changes as explicit follow-up designs until their contracts and regression tests are ready.

The observed synchronous native dictionary lookup also warrants profiling against the reported lag, but moving it to a background task needs stale-result/cancellation/navigation tests. The current cache patch only reduces repeated work while filtering and does not fix that path.

No blanket account login, biometric gate, root/ROM blocking, mandatory cloud integrity SDK, custom cryptography, permission removal or SDK-target bump is part of this work. Such changes need a concrete threat and compatibility case; they are not prerequisites for a useful offline FOSS translator.

## Test and stop rules

First build an unchanged complete checkout. Then run affected unit/instrumentation checks and the controlled device scenarios above for each implemented change. Include release-mode payload logging/egress checks and a second independently signed client for IPC/API cases. Test normal completion, denial, cancellation, process death, restore and rollback; preserve drafts and existing language packs. Never use real private text in test captures.

Do not weaken TLS or introduce production-trusted interception certificates to make a test pass. App-layer network inspectors may miss native code and external provider processes; absence in one inspector is not proof of no egress. Offline success proves availability, while the online controlled trace addresses unexpected transmission. Neither alone establishes universal privacy.

Deliver a baseline when its stated controls and regressions pass, with residual risks recorded. Do not keep adding controls to pursue an undefined "secure" label. This workspace has not executed Android builds/device/security tests. No fork changes, upstream messages, new APK or release were published by this session.
